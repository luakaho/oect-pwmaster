# OECT-PWMaster — 玩客云 OEC / OEC-Turbo（RK3566，fnOS）温控风扇

用一颗 4 线 PWM 风扇，给没有风扇接口的 OEC 做**按温度自动调速**，并提供一个网页面板。

- 硬件只占用主板上 **LED 焊盘**的两个脚，不动 DEBUG 串口
- 软件 = 一个约 300 行的 C 守护进程 + 一个单文件 WebUI，Docker 一键起
- **读取 CPU 与硬盘温度，自动调速**（硬盘数量不影响使用）
- 曲线、回差、限幅、升温趋势加力、手动档都能在网页里调，每一项都有中文说明

> 只在 **OEC-1.1（OEC / OEC-Turbo，RK3566）** 上验证过。其他板子原理相同，但引脚名要自己核对。

---

## 1. 它到底怎么控制风扇的

OEC 这块板有几个硬性限制（都实测过）：

- **没有风扇接口**，也没有可用的硬件 PWM（两个 PWM 通道被 CPU/逻辑电压占用了）
- **没有 PMIC**，关机后 12V 一直在
- 主板上唯一方便焊接、且本来就是 GPIO 功能的，是那排 **LED 焊盘**：`LED-B / LED-G / VCC3V3 / LED-R`

所以方案是：

| 用途 | 引脚 | 说明 |
|---|---|---|
| 风扇 PWM 信号 | **LED-G**（gpiochip3 line12） | 软件产生 25kHz↓ 方波（默认 12kHz） |
| 风扇测速（可选） | LED-R（gpiochip0 line19） | 本仓库默认**不接管**，见下方安全说明 |
| 指示灯 | LED-B（丝印，gpiochip3 line11） | 守护进程让它常亮；**具体亮什么颜色未验证，以你板子为准** |
| 风扇 12V / GND | 板外 12V（见接线） | 风扇电源不走主板 |

守护进程启动时会把内核的 `leds-gpio` 驱动 **unbind**（否则这些脚被灯驱动占着，写电平会失败），退出时再 bind 回去。

| 设备 | 玩客云 OEC-Turbo（主板 OEC-1.1），RK3566 四核 / 4GB / 8GB eMMC |
| 系统 | fnOS（Debian 12，trim 内核 6.18.18.c1090-trim） |

| 指示灯 | 蓝灯由守护进程驱动常亮；红灯（TACH 那个脚）不做驱动，状态未知 |

> 你的机器如果没改过多盘，只有 1 块盘也没问题——软件会自动识别盘的数量。

## 3. 接线

### 3.1 先认清风扇 4 根线

常见 4 线风扇的针序是 **1 GND / 2 +12V / 3 TACH / 4 PWM**（2510-4P），线色通常是 **黑 / 黄 / 绿 / 蓝**，但不同厂家可能不同。**以你风扇的标称或说明书为准**，不要只按颜色判断。
买到的扇子务必按**颜色**再核对一遍针序。

### 3.2 主板侧：焊哪两个点

主板上靠近 SATA 排线有一排 4 个焊盘，丝印是：

```
LED-B   LED-G   VCC3V3   LED-R
```

- **PWM 线（蓝）→ 丝印 `LED-G` 的那个焊盘**（以焊盘旁的丝印为准，不要按位置数）
- 需要测速时才接 **TACH（绿）→ LED-R**（第 4 个）——**先看 3.4 的安全说明，本仓库默认不接**

焊点很小，建议：先给焊盘上锡 → 线头挂锡 → 点焊 → 热熔胶固定出线。**焊前一定拔掉 12V。**

> 说明：丝印上写的是 `LED-B / LED-G / VCC3V3 / LED-R`，本项目**只确认并只使用 `LED-G` 这个焊盘**做 PWM；其余三个焊盘的电气行为（会不会点亮某个灯、有没有 3.3V 之类）**未做完整验证**，请勿随意接信号线上去。

### 3.3 PWM 下拉（可选但推荐）

在 **LED-G 与 GND 之间**跨一个 **10kΩ** 电阻。

- 4 线扇的 PWM 脚内部上拉，一旦线悬空（程序崩溃/关机）= 100% 满速
- 加了下拉，失灵时变成 0% 停转，更符合“安静优先”

### 3.4 关于测速（TACH）——**目前未验证，默认不接**

本项目的作者在自己的机器上试过把 TACH 焊到 **LED-R** 焊盘，结果是：**转速读不到，而且红灯表现异常（常亮/发紫）**。具体原因**尚未实测确认**，目前有两种可能：

- 风扇的 TACH 是开漏输出、需要主机侧上拉，而板子这侧没有合适的上拉 → 读不到脉冲；
- 该脚上可能存在我们不认识的电路（例如被 LED 通路影响），或者焊接时与相邻焊盘有轻微搭连。

**因此本仓库默认完全不碰 LED-R**：守护进程不申请也不读取该引脚，状态里 `rpm` 显示 `-1 = 未启用`。风扇调速**不依赖**测速，接不接 TACH 都能正常工作。

如果你自己想试着恢复测速，建议按这个顺序来（**每一项做完再上电**）：

1. 断电，确认绿线只接在 **LED-R** 一个焊盘上，没有和相邻的 `VCC3V3` 搭连；
2. 上电后量 **LED-R 对 GND** 的电压，并记录数值：
   - 稳定在 **0–3.3V** → 相对安全，可尝试在 LED-R 与 VCC3V3 之间加 **10kΩ 上拉**后再试；
   - **接近 5V** → 说明有 5V 反送，**不要接**，直接把绿线剪断；
3. 需要软件支持的话，把 `fanctl.c` 里标注 `SAFE MODE` 的两处打开（申请 LED-R 为输入 + 启动 tach 线程），重新编译；
4. 读数仍为 0 就放弃测速——这只影响“看转速”，不影响温控。

> 这一节描述的是**现象与推测**，不是已验证结论；不同板子/风扇下表现可能不同。

### 3.5 12V 供电

方案**需要一路稳定的 12V**（风扇标称 12V），例如常见的 12V/2A 适配器或设备本身已有的 12V 供电。**具体从哪里取电、怎么接线由你自己决定，本项目不做限定**，只要注意：

- 风扇的 GND 与主板 **共地**
- 上电前先用万用表确认极性和电压，别把 12V 接到逻辑焊盘上

### 3.6 汇总接线表

| 风扇线 | 接到 |
|---|---|
| 黑 GND | 12V 电源负极（与主板共地） |
| 黄 +12V | 12V 电源正极 |
| 蓝 PWM | 主板 **LED-G** 焊盘 |
| 绿 TACH | 默认**不接**；要接请看 3.4（先量电压） |

## 4. 安装（Docker，一条命令）

前提：装好 Docker / Docker Compose 的 fnOS（或其他 Linux）。

```bash
git clone <本仓库地址> oect-pwmaster
cd oect-pwmaster
docker compose up -d --build
```

首次构建会拉两个小镜像（`alpine:3.19` 做编译、`python:3.11-slim` 做运行），apk 走阿里云镜像源，国内一般 **1–2 分钟**完成；C 代码用 musl **静态链接**，编译产物可直接跑在 glibc 镜像里。

打开 `http://<NAS_IP>:8090` 就是面板。

首次启动会在 `./data/` 生成配置和日志：

```
data/
├── config/fan.conf     # 所有参数
├── fan.log             # 采样日志
├── status.json         # 当前状态
└── manual.duty         # 存在即代表手动档
```

### 容器为什么用 privileged

守护进程要：

- 打开 `/dev/gpiochip0`、`/dev/gpiochip3`（`-v /dev:/dev`）
- 写 `/sys/bus/platform/drivers/leds-gpio/unbind` 把 LED 驱动让出来（`-v /sys:/sys` 且需要特权）
- 挂 `/etc/localtime` 或传 `TZ`，否则日志时间会是 UTC

如果你不接受 privileged，可以改成 **宿主机直接跑**（见第 9 节）。

## 5. 网页面板

> 默认界面只露**温度状态、曲线图、三个一键方案**；曲线、手动控制、阈值等全部收在 **「专业设置」** 折叠区里，点开才能改。

- **状态**：CPU 温度、所有硬盘温度、当前档位、转速（未接测速时显示“未启用”）、模式
- **曲线图**：最近约 6 分钟的 CPU / 最高盘温 / 档位
- **手动**：滑杆 0–100% + 回到自动
- **一键方案**（整套参数一起换）：
  - **静音**：38℃ 起转
  - **均衡**：33℃ 起转（默认）
  - **强冷**：30℃ 起转
- **两条曲线**：各 6 个温度点，`温度 → 占空比`
- **其它设置**：起转/停止温度、最小/最大档位、失效保底、硬盘取值方式、刷新间隔、升温加速与上限
- 每个标题后面的 `?` 点开就是中文说明

## 6. 配置项（`data/config/fan.conf`）

| 键 | 含义 | 默认 |
|---|---|---|
| `cpu_curve` | CPU 温度曲线，`温度:占空比` 逗号分隔，≤6 点 | `33:25,40:50,48:75,58:100` |
| `hdd_curve` | 硬盘温度曲线（同上）。**第一个点建议写 0**，否则低于起点也会转 | `35:0,40:40,45:65,50:100` |
| `hyst_start` | CPU 达到该温度才起转 | `33` |
| `hyst_stop` | CPU 低于该温度才停（回差） | `31` |
| `min_duty` / `max_duty` | 总限幅（%） | `0` / `100` |
| `failsafe_duty` | 读不到温度时的保底档位 | `60` |
| `hdd_mode` | 多块盘时怎么合成一个温度：`max`＝取最高（推荐）、`avg`＝取平均；只有一块盘时两者等价 | `max` |
| `update_sec` | 采样间隔（秒） | `2` |
| `boost_gain` | 升 1℃/分 额外加多少 %（仅当风扇已在转） | `15` |
| `boost_max` | 额外加力上限 % | `30` |
| `freq` | 软件 PWM 频率（Hz） | `12000` |
| `spin_us` | 每个边沿的自旋窗口（微秒） | `4` |
| `deadband_duty` | 低于该占空比直接判 0（省 CPU） | `12` |

改完保存，**2 秒内热加载**，不需要重启。

## 7. 性能：为什么是 12kHz，而不是风扇规格书上的 25kHz

大多数 4 线风扇的 PWM 输入按 25kHz 设计，但 OEC 没有可用的硬件 PWM，只能用软件定时翻转 GPIO。实测（RK3566，duty 50%）：

| 频率 | 守护进程占用 |
|---|---|
| 25kHz | **约 100% 单核** |
| 15kHz | 约 100% 单核 |
| **12kHz** | **约 24–26% 单核** |
| 8kHz | 约 24% 单核 |
| 5kHz | 约 20% 单核 |

原因：25kHz 半周期只有 20µs，比系统定时器精度还短，只能全程自旋；12kHz 起可以“先睡、最后几微秒自旋补足”。

**默认 12kHz**：绝大多数人听不到（高频特性在机箱里基本听不出来），而 CPU 少烧 3/4。
如果你耳朵能听到“嘶”声，把 `freq` 改成 `25000`（代价是一个核），或改 `20000` 折中。

另外加了 **死区 12%**：低于该档位风扇根本转不起来，直接判 0，避免无效自旋。实测空闲时只占 4.5% 单核。

## 8. 故障排查

**Q：网页打开是空白 / 全是 `--`**
A：先看浏览器控制台有没有 JS 报错；再 `docker logs oect-pwmaster`。

**Q：风扇不转**
1. 面板里点“手动”拉到 100%，看是否转 → 不转说明 12V 或 PWM 线有问题
2. 量 LED-G 对 GND：手动 100% 时约 3.3V、0% 时 0V
3. 量风扇黄线对黑线：应 12V

**Q：转速读不到 / 指示灯颜色异常（如偏红、发紫）**
A：正常，本仓库默认不接测速。要接请看 3.4，先量电压，5V 就别接。

**Q：风扇一直转不停**
- 检查 `hdd_curve` 第一个点是不是写了非 0（比如 `33:20`）
- 检查 `min_duty` 是否被设成了 20+

**Q：改配置没反应**
- `cat data/status.json` 看 `hyst_start` 等字段有没有变（变了说明已加载）
- 温度低于 `hyst_start` 时风扇本来就不转，这是回差逻辑

**Q：LED 灯全灭了**
A：守护进程接管了 LED 线，所以灯的颜色/数量可能与你原来的印象不同；**灯色对应关系尚未验证**，只要功能正常就不用管。停掉容器会自动把 `leds-gpio` bind 回去，恢复原状。

**Q：容器起不来，报 permission**
A：确认 `privileged: true`，并且 `/dev`、`/sys` 都挂上了。

## 9. 不用 Docker：宿主机直跑（可选）

```bash
gcc -O2 -pthread -o /usr/local/sbin/fanctl fanctl.c
mkdir -p /vol1/1000/fan/config
cp config.example /vol1/1000/fan/config/fan.conf
FAN_DATA=/vol1/1000/fan /usr/local/sbin/fanctl     # 前台试跑
```

要开机自启就写个 systemd unit：

```ini
[Unit]
Description=OEC fan control
After=local-fs.target

[Service]
Environment=FAN_DATA=/vol1/1000/fan
ExecStart=/usr/local/sbin/fanctl
Restart=always

[Install]
WantedBy=multi-user.target
```

WebUI 也可以用 `python3 web/server.py`（需要 `FAN_DATA`、`PORT` 环境变量）。

## 10. 卸载 / 回退

```bash
docker compose down
```

- 守护进程退出时会把 `leds-gpio` **bind 回去**，三个灯恢复原状
- 焊上的线可以留着（不接风扇也不影响），或剪断
- 没有任何系统文件被永久修改（除了你手动建的 `data/` 目录）

## 11. 已知限制

- 只有 OEC-1.1 验证过；其他 RK3566 板子要自己找 GPIO 焊点
- 软件 PWM 会占一个核的一部分（12kHz 约 1/4 核）
- 转速默认不可用（见 3.4）
- 无法通过软件控制风扇正反转（4 线扇没有方向控制线，要换向只能物理翻转扇子）
- **未验证事项**：① LED-R 测速脚的电压特性与“红灯异常”的成因；② LED-B / LED-R / VCC3V3 三个焊盘的实际行为与灯色对应关系；③ 不同风扇品牌下 TACH 是否可用
